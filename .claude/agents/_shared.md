# Общие правила для всех агентов

## КРИТИЧНО (ломает проект)

### Архитектура

Проект — Astro 5 SSG (одностраничник). Не переключать на SSR. Не менять деплой/конфиги без явного решения. Стек: Astro 5 + Sanity CMS + Tailwind 4, два языка (EN/RU).

### i18n fallback

Источник контента — **EN** (RU — перевод). Порядок fallback важен: `lang → en → ''`

```typescript
// ❌ BAD
content?.[lang] || 'default text'
content?.[lang] || content?.ru || ''   // ru НЕ источник в этом проекте

// ✅ GOOD
content?.[lang] || content?.en || ''
```

Это зеркало контракта (`CONTRACT.md`): `value[lang] || value.en || ''`. Astro i18n: `defaultLocale: 'en'`, `locales: ['en','ru']`, `prefixDefaultLocale: false` → EN без префикса (`/`), RU с префиксом (`/ru`).

## Принципы кода

- Не дублируй логику — одна идея в одном месте, изменения делаются один раз
- Не добавляй функциональность без явной задачи — никакого «на будущее»
- Выбирай самое простое рабочее решение — минимально необходимое, без лишних абстракций
- Один компонент / функция = одна задача — если делает две вещи, раздели
- Композиция вместо наследования — мелкие компоненты собираются в крупные, без жёстких иерархий

## ВАЖНО (требует подтверждения)

### Источники истины

- `CONTRACT.md` — имена полей Sanity + GROQ-проекции. Studio и фронт обязаны совпадать. Менять только синхронно в обоих местах.
- `CLAUDE.md` — архитектура, команды, локализация, фишки Studio.

### Sanity

Документы проекта: `siteSettings` (Hero + SEO, singleton), `aboutSection` (About, singleton), `section` (произвольные разделы портфолио, orderable), `contactSettings` (Контакты, singleton). Sanity — источник истины для контента.

Не удалять поля схем без deprecation-фазы. i18n fallback (см. выше) распространяется и на Sanity-данные: `data?.field?.[lang] || data?.field?.en || ''`. Не использовать `data?.title || 'Untitled'` — теряется мультиязычность.

Локализованные object-типы: `localeString` `{en, ru}`, `localeText` `{en, ru}`, `localeRichText` `{en: block[], ru: block[]}`. Локализованные поля в GROQ тянем целиком (`{en, ru}`), локализацию делаем на фронте.

### Git

- Работаем в `main`, без feature-веток.
- Не делать `git commit/push` без явного запроса.

### Секреты

Не выводить API-ключи, токены, пароли в логи и ответы. `.env` не коммитить (он в `.gitignore`).

### CSS и стили

CSS-стили — через классы, не инлайн:

```
❌ BAD — хардкод в разметке
class="text-white/60 hover:text-white transition-all duration-300"
style="color: rgba(255,255,255,0.6)"

✅ GOOD — классы и токены
class="..."           ← цвет/типографика определены в @layer components / @theme
```

**Правила:**
- Стили компонентов — через классы в `src/styles/global.css` → `@layer components`
- Цвета — через `@theme`-токены, не rgba/hex-хардкод
- Hover/transition/animation — через CSS-классы, не Tailwind arbitrary values в разметке
- Новый визуальный паттерн → сначала класс в `@layer components`, потом использование
- Сначала ищи существующее: перед тем как писать CSS-значение — проверь существующие классы и токены в `src/styles/global.css`. Подходящий есть — используй его

**Область видимости:**
- `.astro` файлы — ТОЛЬКО классы (Tailwind / `@layer components`), никогда `style=""`
- `.tsx`/React-острова — классы + `style={{}}` допустимо ТОЛЬКО для динамических значений (вычисляемых в JS). Статичные цвета, размеры, отступы → через className

**ЗАПРЕЩЕНО (проверяй в своём diff):**
- `rgba(...)`, `hsla(...)`, hex-цвета → использовать `var(--color-*)` или классы из `@layer components`
- `text-white/XX`, `text-black/XX` → использовать токены
- `opacity-XX` inline → определить в CSS-классе
- Произвольные `hover:`, `transition-*`, `duration-*` в разметке → CSS-класс в `@layer components`
- `style="..."` для цвета, размера, отступа → Tailwind-класс или CSS-класс
- Если в соседнем коде есть хардкод — не копировать, заменить на токен

> Примечание: фронт пока в начале сборки (`src/` минимален). Если файла `src/styles/global.css` ещё нет — он создаётся в рамках задачи; правила выше действуют с первого CSS.

### Коммиты

Conventional commits (feat/fix/style/docs/chore). Тело на русском. Ссылка на issue если есть: `feat: добавил блок разделов (#12)`.

### Визуальная проверка (Playwright)

❌ НЕ запускать Playwright (browser_navigate, browser_take_screenshot, browser_snapshot и др.) без явного запроса пользователя.

Если считаешь проверку нужной — опиши зачем и спроси: «Хочешь, проверю визуально через Playwright?»

Артефакты Playwright (скриншоты, снапшоты) — в папку `temp/` внутри проекта, имя `YYYY-MM-DD_playwright_<название>.<ext>`.

## WORKFLOW

### Субагентные промпты

В `.claude/agents/` есть инструкции для типовых задач. Читай соответствующий промпт **перед выполнением**:

| Задача | Промпт | Кто | Когда читать |
|--------|--------|-----|-------------|
| Новая/изменённая Sanity-схема | `sanity-schema.md` | Developer | Работа с типами в `studio/schemaTypes/` |

Если задача подпадает под промпт — сначала прочитай его, потом действуй.

### Верификация

`npm run build` — для проверки сборки (hot reload работает в dev, не нужно билдить после каждой правки). Lint/test в проекте нет. Astro-конфиг вынесен в `config/astro.config.mjs` (уже в npm-скриптах).

### Доказательства до утверждений

Перед заявлением «готово» — подтверди результат фактами. Проверка зависит от задачи: grep по изменённым паттернам, build, чтение итогового файла, проверка что `npm run dev` рендерит нужное. Не утверждай «работает», пока не убедился. Если проверка невозможна — скажи, что именно не проверено.

### Факты vs предположения

Факт (поведение либы, причина бага, статус сервиса) — проверить (код, доки, build) и сослаться, либо пометить: **Непроверенная информация:** … Гипотеза ≠ причина.

### Сессии и контекст

Каждый агент — отдельная сессия Claude Code. Контекст между агентами передаётся только через файлы задач (`.work/tasks/`).

### Завершение работы

После завершения агент делает одно из:
- **Успешно, последний в цепочке** → спрашивает User: «Сделать commit, push?»
- **Есть следующий агент** → выдаёт промпт со ссылкой на файл задачи
- **Не может выполнить** → статус задачи `Заблокирована`, описывает причину в «Выполнение», выдаёт промпт для PM

### Dev окружение

Не запускать новый localhost, если он уже запущен. Порты: Astro dev — `http://localhost:4321`, Sanity Studio — `http://localhost:3333`.

### Фоновые процессы

Не оставлять long-running процессы (dev-серверы, watch, `tsc --watch`). Если запустил процесс для проверки — останови перед завершением. Команды типа `npx tsc --noEmit`, `npm run build` допустимы (завершаются сами). Команды типа `npm run dev`, `sanity dev` — только если явно просит пользователь, и не в фоне после выполнения задачи.

### Деплой

Деплой пока НЕ настроен (нет домена/сервера). Сайт собирается (`npm run build`), деплой — позже. Не выдумывать команды деплоя, не настраивать VPS/CI без явной задачи.
